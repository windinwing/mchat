# 多股全渠道体检工作流（含飞书通知）+ batch 子图增强 + 节点必填校验

## 一、后端：升级 batch 子图执行器（核心改动）

**现状问题**：`_run_batch_child`（workflow_service.py:1316-1356）是**串行**循环、**只跑 skill 子节点**（merge/condition 子节点被跳过）。所以 batch 子图放不了「采集→merge→分析」结构。

**改造**：把 `_run_batch_child` 重写成**迷你图执行器**（镜像主执行器的 wave 并行模型）：
- 就绪队列 + 拓扑序：同一层无依赖的子节点（如 7 个采集 skill）**用 `asyncio.gather` 并发执行**
- 支持 3 类子节点：
  - `skill`：渲染 payload、执行（现有逻辑）
  - `merge`：等所有上游子节点完成，构建 `sections`（复制主执行器 merge 逻辑 L1244-1257，用子图的 `child_incoming`/`local_outputs`）
  - `condition`：复用主执行器 condition 逻辑
- 子节点上下文仍是 `local_outputs = {input, nodes, item, item_value}`，merge 的 `sections` 写进 `local_outputs['nodes'][mergeId]`，分析节点用 `${nodes.merge.sections}` 读取
- 每个 batch item 仍独立 DB session + Semaphore 并发控制（保持不变）
- 失败处理：某子节点失败记录 status=failed，不中断同层其他节点；merge 跳过失败的上游

这样 batch 子图就能放完整的「7 采集并行 → merge → analysis」结构，每支股票各自跑一遍。

## 二、新模板：STOCK_BATCH_FULL_CHECKUP

在 `stock_workflow_templates.py` 新增，结构：
```
start(codes: 多行文本)
  → batch(list_path=input.codes, max_concurrent=2)
       ├─ quote       payload {code: ${item.line}}
       ├─ capital     payload {code: ${item.line}}
       ├─ fundamentals
       ├─ research
       ├─ news
       ├─ announcement
       ├─ sentiment    （7 个采集并行）
       ├─ merge        （sections 汇总这 7 个）
       └─ analysis     payload {code: ${item.line}, sections: ${nodes.merge.sections}, scenario: 全面体检}
  → feishu-push  payload {webhook_url: ${input.feishu_webhook}, content: 汇总每支结果}
  → end
```
- start 输入：`codes`（多行）+ `feishu_webhook`（飞书 webhook，选填，留空则不推送）
- 采集→merge→分析 子图复用现有 `_CHANNELS` 表 + `_analysis_node`
- 飞书节点在 batch **之后**：汇总 `${nodes.batch.result.items}`，拼成「N 支股票分析完成：股票A 得分/方向；股票B…」
- 注册到 `STOCK_TEMPLATES`

## 三、飞书节点 content 模板

batch 之后，飞书 content 用 `${nodes.batch.result.items}`——但这是数组，模板渲染会 stringify。为了让汇总可读，飞书节点的 content 用一个**简单拼接**：
- 后端 `_render_template` 对数组 stringify 不可控
- **方案**：飞书节点 content 直接绑 `${nodes.batch.result.items}` 的简化形式 —— 实际上让 feishu-push skill 支持 `content` 里有 JSON 数组时自动格式化（main.py 里：如果 content 是 batch items 的 JSON，提取每项 code/score/direction 拼成多行）

所以给 feishu-push 加一个 `summary_from_batch` 能力：当 content 为空但检测到上游 batch 结果时，自动生成「✅ 股票分析完成（N 支）：600519 综合得分 72 偏多；000001 ...」。但更简单可控的做法：**模板里直接写死 content 文本 + 绑定关键字段**，feishu 节点 content 写：
```
"股票批量分析完成：${nodes.batch.result.count} 支"
```
第一版用这个简单绑定，避免复杂的数组渲染。

## 四、节点字段必填校验（前端 + 后端）

**前端**（图形编排）：
- `SkillParamFieldDef` 加 `required?: boolean`（skillParamSchemas.ts）
- `resolveSkillParamFields` 透传 workflow_fields 里的 required（已 spread，只需类型声明）
- `PayloadMapper.tsx`：required 字段 label 加红星 `*`，空值时输入框红框 + 提示
- 执行前校验：WorkflowsPage 的 `confirmRun` + run 按钮，遍历选中节点的 payload，缺必填报错不让跑

**后端**：skill 节点执行前，校验 workflow_fields 里 required 的 key 是否在 payload 里（新增校验逻辑，缺则 raise 友好错误）。复用 start 节点的校验模式。

**范围控制**：只给 feishu-push（webhook_url, content）、stock 技能（code）这类关键字段标 required。不强制改所有技能。
