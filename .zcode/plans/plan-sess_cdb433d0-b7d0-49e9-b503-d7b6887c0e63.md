# 用户角色全流程体验改进方案

## 审计发现的核心问题（按优先级）

经完整排查 user/agent 角色工作流全流程，确认这些"用户看不到友好提示"的痛点：

1. **依赖安装无提示**：首次执行 stock 工作流时，pip install 30-60s，全程只显示"后台生成报告中"的 spinner，无"正在安装依赖"提示
2. **权限拒绝无引导**：graph 编辑器保存时 free 用户被拒（402），只弹一个红色 toast 原始消息，无升级引导；模板创建同理
3. **错误是原始 traceback**：`workflows.detailError` 直接显示 `str(exc)[:2000]`（含完整 Python traceback、文件路径、pip stderr），用户看不懂
4. **"node failed" 无信息**：节点错误为空时显示字面量 "node failed"

## 方案（4 块，聚焦高价值）

### 1. 依赖安装友好提示（前端 + 后端）

**后端** `workflow_service.py`：
- `run_once` 时，若 workflow 含 stock-* skill，给 run 记录加 `note: "首次执行需安装依赖，预计 30-60 秒"`（或用 input_payload 的元数据标记）
- 更稳的做法：在 `_execute_graph_workflow` 执行 skill 节点前，检测 requirements.txt 是否需要安装，若需要则**先更新 run 状态为带提示的 running**（写一个 progress 注释到 output_payload）

**实际采用（轻量）**：不改执行链路（风险大），改为：
- 前端轮询时，running 状态显示**更详细的提示**："正在执行，首次运行可能需安装依赖（约1分钟）"
- 新增 i18n key `runInProgressFirstRunHint`

### 2. 错误信息友好化（前端，最高价值）

`WorkflowsPage.tsx` 的错误显示区（line 1362-1371）+ `WorkflowRunOverlay.tsx`：
- 新增 `humanizeRunError(error: string)` 函数，把原始 traceback 转成用户可读的提示：
  - `ModuleNotFoundError: No module named 'pandas'` → "技能依赖缺失（pandas），正在自动安装，请稍后重试；如持续报错请联系管理员"
  - `pip install failed` / `容器内依赖安装失败` → "依赖安装失败，请稍后重试或联系管理员"
  - `Connection`/`Timeout` → "网络连接超时，请稍后重试"
  - `Too Many Requests` → "数据源请求过于频繁，请稍后再试"
  - 其他 → 截断保留前 3 行 + "详细日志"可折叠展开原始错误
- 原始 traceback 放进 `<details>` 折叠（默认收起），顶部显示友好提示
- `node failed` → "节点执行失败，无详细错误信息"

### 3. 权限拒绝引导升级（前端）

**`WorkflowGraphPage.tsx`** handleSave（line 71-85）：
- 用 `extractAutomationLimit` + `showLimitToast` 替换原始 toast（对齐 WorkflowsPage 的处理）
- portal 用户 402 时跳转 checkout

**`WorkflowsPage.tsx`** openCreate（line 357）：
- entitlements 为 null 时也禁用创建按钮 + 提示"权益加载中"，而不是让用户填完表单才报错

### 4. 节点级状态可见性（前端，体验提升）

`WorkflowsPage.tsx` 运行详情弹窗：
- running 状态时，若 `selectedRunDetail.node_runs` 有数据，显示已完成的节点列表（✓/⏳ 图标），让用户看到进度
- 注：当前 node_runs 是执行完才写 DB，所以 running 时看不到——这块**不改后端**（改执行链路风险大），只在有数据时显示

## 不做（控制范围）
- 不改 `_execute_graph_workflow` 的中间状态写入（风险高，影响所有工作流）
- 不改 entitlements 计费逻辑
- 不加新的预检/warm 机制
- 不改 admin 角色（admin 无限制，无此问题）

## 实施顺序
1. 错误信息友好化（humanizeRunError + 折叠原始错误）— 最高价值
2. 依赖安装提示（running banner 文案 + i18n）
3. graph 保存的 402 引导
4. 节点状态可见性（best-effort）
5. i18n keys
6. tsc + build + 部署

## 验证
- tsc + build 通过
- 手动测：构造一个失败 run，确认显示友好提示 + 可折叠原始错误
- 测 graph 保存的 402 引导（若能模拟 portal free 用户）

这个方案聚焦"用户能看到友好提示"，改动集中在前端错误处理 + 文案，后端几乎不动（降低线上风险）。要我开始吗？
